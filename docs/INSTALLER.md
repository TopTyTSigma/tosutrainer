# ToSU! Trainer! — онлайн-установщик

Самостоятельный Windows x64 установщик на Go, без npm-зависимостей и без встраивания пакета приложения. Интерфейс на русском. Исходный `D:\lazer-danser\installer` не изменён.

## Запуск

Готовая сборка: `dist\ToSU-Trainer-Setup.exe`.

Пока блок `github` в `config.json` пуст, окно открывается, выбор папки работает, но установка заблокирована. Сетевых запросов к GitHub в этом состоянии нет. Фиктивная установка или генерация файлов приложения не выполняется.

По умолчанию папка установки — `%LOCALAPPDATA%\ToSU-Trainer`. Исполняемый файл приложения — `trainerSU.exe`, согласно `AssemblyName` в `osu.Desktop.csproj`. Название — **ToSU! Trainer!**. Иконка скопирована из `D:\osu src\osu-master\osu.Desktop\lazer.ico` в `assets\installer.ico`; эта же иконка используется в EXE и HTML.

## Сборка

Нужны Windows, Go 1.24+ и GNU windres с поддержкой `pe-x86-64`. Внешних Go-модулей нет. Установщик не требует Go на компьютере пользователя.

```powershell
cd 'D:\osu src\installer'
.\build.ps1 -Go 'C:\Program Files\Go\bin\go.exe' -Windres 'D:\library\bin\windres.exe'
```

Скрипт компилирует иконку, Windows manifest и VERSIONINFO, запускает `go vet` и создаёт GUI EXE без консольного окна. Manifest запрашивает обычные права пользователя, не UAC elevation.

Для разработки с видимой консолью:

```powershell
& 'C:\Program Files\Go\bin\go.exe' run .
# Только локальный сервер, без открытия браузера:
& 'C:\Program Files\Go\bin\go.exe' run . --no-window
```

В режиме `--no-window` URL с одноразовым ключом выводится в stdout; его нужно открыть целиком. Такой URL нельзя публиковать. Сервер в этом режиме работает до команды «Закрыть» или остановки процесса. Обычный запуск не печатает ключ в журнал.

## Как подключить GitHub после публикации

1. Собрать **готовый дистрибутив Windows x64**, не ZIP исходного кода. Включить необходимые DLL, ресурсы и runtime либо отдельно определить требования к установленному runtime. Установщик сам .NET и другие зависимости не устанавливает.
2. Упаковать содержимое папки дистрибутива в ZIP: `trainerSU.exe` должен лежать непосредственно в корне архива, а не во вложенной папке с версией.
3. Создать публичный GitHub Release с фиксированным тегом, загрузить ZIP как release asset. Приватные репозитории и авторизация пока не поддерживаются.
4. Получить размер ZIP, SHA-256 и суммарный распакованный размер файлов:

```powershell
$zipPath = 'D:\releases\ToSU-Trainer-win-x64.zip' # пример, замените своим путём
(Get-Item $zipPath).Length
$stream = [IO.File]::OpenRead($zipPath)
$sha = [Security.Cryptography.SHA256]::Create()
try {
    [BitConverter]::ToString($sha.ComputeHash($stream)).Replace('-', '').ToLowerInvariant()
} finally {
    $stream.Dispose()
    $sha.Dispose()
}
Add-Type -AssemblyName System.IO.Compression.FileSystem
$zip = [IO.Compression.ZipFile]::OpenRead($zipPath)
try {
    ($zip.Entries | Measure-Object -Property Length -Sum).Sum
} finally {
    $zip.Dispose()
}
```

5. Заполнить `config.json`. Пример схемы ниже **не является рабочим релизом** — заменить все значения своим asset:

```json
{
  "product": "ToSU! Trainer!",
  "folderName": "ToSU-Trainer",
  "executable": "trainerSU.exe",
  "github": {
    "owner": "YOUR-OWNER",
    "repository": "YOUR-REPOSITORY",
    "tag": "v1.0.0",
    "asset": "ToSU-Trainer-win-x64.zip",
    "sha256": "REPLACE-WITH-64-HEX-CHARACTERS",
    "sizeBytes": 123456789,
    "unpackedBytes": 345678901
  }
}
```

6. Пересобрать установщик. Конфигурация **встроена в EXE**; изменение JSON рядом с готовым EXE не меняет его поведение.

URL строится как `https://github.com/{owner}/{repository}/releases/download/{tag}/{asset}`. `latest`, загрузка удалённого манифеста и автообновление намеренно не используются: URL и ожидаемый хеш закрепляются в сборке. Для нового пакета требуется новая сборка установщика. SHA-256 защищает от повреждения/подмены относительно встроенного доверенного значения, но не заменяет Authenticode-подпись самого установщика.

## Архитектура исходного установщика

Это **не встроенный WebView2** и не Electron:

```text
Go EXE
 ├─ embed: HTML / CSS / JS + offline payload ZIP
 ├─ HTTP server: 127.0.0.1, динамический порт
 ├─ REST-команды + SSE progress + heartbeat
 ├─ msedge.exe --app=URL --user-data-dir=TEMP
 └─ native Windows API / PowerShell: папки, диск, ярлыки
```

Изучены `main.go`, `edge.go`, `server.go`, `install.go`, `payload.go`, `dialog.go`, `shortcuts.go`, `web/index.html` и `web/app.js` оригинала.

Полезные решения оригинала сохранены: встраиваемый web-интерфейс, loopback-сервер, отдельный профиль Edge, резервное открытие браузера, отслеживание окна по активности страницы (а не времени жизни msedge-процесса), русский UI.

Отличия скелета:

- Вместо встроенного ZIP — GitHub Release asset с фиксированным SHA-256.
- Вместо прямой записи в конечную папку — staging на том же диске и неперезаписывающий `MoveFile` только после проверки и распаковки.
- В оригинале SSE — отдельные события без воспроизведения; здесь каждое событие — полный снимок состояния с ревизией. После F5/переподключения приходит актуальное состояние, включая ошибку или завершение. Медленному подписчику оставляется последний снимок.
- Все API защищены ключом, проверкой Host/Origin и запретом cross-site запросов. Статика не содержит ключ; он передаётся окну в URL fragment и сохраняется в sessionStorage. Для SSE ключ идёт в query, access-log не ведётся.
- Лимиты JSON, заголовков, ZIP, распакованного размера; CSP без сторонних ресурсов и inline-скриптов.
- Нет автоматического снятия `Zone.Identifier`, отключения защитных функций Edge или запуска приложения без нажатия пользователем кнопки.

## Структура

| Файл | Назначение |
| --- | --- |
| `main.go` | Запуск, журналы, цикл жизни HTTP и окна |
| `config.go`, `config.json` | Встроенная конфигурация, проверка полей GitHub |
| `server.go` | API, SSE, защита loopback-интерфейса |
| `engine.go` | Состояние операции, отмена, место на диске, блокировка папки, staging и commit |
| `download.go` | HTTPS, разрешённые redirect-хосты GitHub, таймауты, до 3 попыток загрузки |
| `archive.go` | SHA-256, проверка ZIP-путей и размеров, распаковка |
| `native_windows.go` | Edge, выбор папки, WinAPI, запуск приложения |
| `web/` | Встроенные HTML/CSS/JS и иконка |
| `assets/` | Иконка, VERSIONINFO, manifest |
| `build.ps1` | Сборка Windows x64 EXE |

## Стабильность и границы текущего скелета

- Операция только одна на процесс. `.install-lock` дополнительно предотвращает одновременную установку в одну папку двумя экземплярами.
- Скачивание потоковое, без хранения всего ZIP в RAM; максимум 3 попытки, повтор начинается с нуля. Таймаут простоя 45 секунд, лимит одной попытки 2 часа. При 404/403 немедленно показывается ошибка.
- После проверки SHA-256 архив распаковывается в уникальную `.tosu-install-*` папку рядом с целевой. Проверяются traversal, абсолютные пути, ADS, Windows device names, симлинки, case-insensitive дубликаты, CRC32 и размеры файлов. Максимум 100000 записей, ZIP до 16 ГиБ, распакованные файлы до 64 ГиБ.
- Перед установкой проверяется доступное пользователю место: архив + распакованные данные + 128 МиБ. Ошибки записи, в том числе заполнение диска во время операции, прерывают установку.
- Целевая папка должна **не существовать**, даже если она пуста. Это намеренное ограничение первой версии, а не механизм обновления.
- Отмена работает во время загрузки/проверки/распаковки. На короткой стадии финального переноса отмена и закрытие через API блокируются.
- Закрытие окна во время установки не обрывает запись: Go продолжит работу. После завершения и отсутствия UI сервер завершится через 30 секунд. Новое окно после полного закрытия процесса не восстанавливает предыдущую операцию.
- Обычные ошибки/отмена очищают staging. После отключения питания или принудительного завершения могут остаться `.tosu-install-*` и `.install-lock`. Удаляйте их вручную **только убедившись, что установщик больше не работает**. Автоматическое восстановление после падения ОС не реализовано.
- Проверка reparse points снижает риск записи через junction. Это не sandbox против другого локального процесса, который одновременно меняет файловую систему с правами пользователя.
- Ошибки и проблемы очистки пишутся в `%LOCALAPPDATA%\ToSU-Trainer-Installer\logs`. Ротации логов пока нет. Старые логи можно удалить вручную.
- Собственная иконка встроена в EXE и показана в UI. Значок панели задач окна Edge контролирует сам Edge; это не полноценное нативное WebView-окно.
- Пока нет ярлыков, деинсталлятора, регистрации в «Приложения», обновления/отката существующей установки, докачки Range, нескольких пакетов, silent-режима, цифровой подписи и bootstrap runtime. Эти функции не имитируются неработающими переключателями.
- Не выполнена реальная установка с GitHub: пакета ещё нет. Перед распространением нужны проверка на чистой Windows, реальный asset, сценарии недоступной сети/отмены/недостатка места и подпись EXE. Успешная сборка сама по себе не доказывает эксплуатационную стабильность.
